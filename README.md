# 牛カード 稼働状況ページ

牛カードの障害・メンテナンスを、**牛カードのアプリとは別の場所**から
お客様にお知らせするためのページです。

- 公開URL: https://status.ushi-card.com/
- 予備URL: https://github.com/hiromi-ushicard/ushi-card-status/blob/main/status.json
  （公開URLが開けないときは、こちらを案内してください。
  見た目は整っていませんが、お知らせの文章そのものが読めます）

> ⚠️ `https://hiromi-ushicard.github.io/ushi-card-status/` は**予備になりません。**
> このURLを開くと、自動で公開URL（`status.ushi-card.com`）へ転送されるためです。
> 公開URLが開けないときは、こちらも同じように開けません（2026-09-05 確認）。

## なぜアプリの外に置いているのか

牛カードのアプリはフロントエンドもAPIも Google Cloud Run の**1サービス**で動いています。
そのサービスが止まると、アプリの中のどのページ（お問い合わせ・利用規約を含む）も開けません。
保守のためにアクセスを止めているときも同じで、アプリの全URLが 403 になります。

つまり **「アプリの中に告知を出す」だけでは、いちばん告知が必要なときに告知が出せません。**
このページは GitHub Pages（Google Cloud とは無関係の場所）で配信しているので、
アプリが止まっていても表示されます。

## 触ってよいファイル

**`status.json` だけです。** ほかのファイルは触らないでください。

`status.json` を書き替えると、次の2つが**同時に**変わります。

1. このページ（https://status.ushi-card.com/）の表示
2. 牛カードのアプリの画面上部に出る帯（バナー）

同じことを2箇所に書く必要はありません。**直すのは `status.json` の1箇所だけ**です。

# お知らせの出しかた（画面の操作だけで完結します）

## 1. 編集画面を開く

1. ブラウザで https://github.com/hiromi-ushicard/ushi-card-status/edit/main/status.json を開く
2. GitHub にログインしていなければログインする
3. 文字を直接書き替えられる画面が開きます

## 2. 障害が起きたときのお知らせ（障害報告）

`"notices": [` のすぐ後ろに、次のかたまりをそのまま貼り付けて、
**`id` ・ `title` ・ `scope` ・ `eta` ・ `at` ・ `body` の6か所**を今回の内容に書き替えます。
（`type` ・ `showInApp` ・ `kind` は、障害のときはこのままで大丈夫です）

```json
    {
      "id": "2026-09-05-login",
      "type": "incident",
      "title": "ログインができない障害が発生しています",
      "scope": "すべてのお客様",
      "eta": "本日15時ごろの復旧を見込んでいます",
      "showInApp": true,
      "reports": [
        {
          "kind": "incident",
          "at": "2026-09-05T13:20:00+09:00",
          "body": "13時10分ごろから、ログインができない状態になっています。原因を調査しています。"
        }
      ]
    },
```

> **いちばん最後の `,` は、そのまま残してください。**
> このページには開設のお知らせがすでに入っているので、ふつうは `,` が必要です。
> `"notices": []` のようにお知らせが1件も無いときだけ、この `,` を消してください。

## 3. 直ったときのお知らせ（復旧報告）

**さきほどのかたまりは消しません。** その中の `reports` の `[` のすぐ後ろに、
次のかたまりを貼り付けて `,` で区切ります（新しい報告を上に足していきます）。

```json
        {
          "kind": "recovery",
          "at": "2026-09-05T14:40:00+09:00",
          "body": "14時35分に復旧しました。ご迷惑をおかけして申し訳ありませんでした。原因は……でした。"
        },
```

`recovery`（復旧報告）を入れると、このページの上部が自動で「正常に稼働しています」に戻り、
そのお知らせに「復旧済み」の印が付きます。**別に「直りました」フラグを立てる必要はありません。**

途中経過を伝えたいときは `"kind": "progress"`（経過報告）を同じ形で足してください。

## 4. 復旧の見込み時刻が変わったとき（15時→18時に延びた、など）

**`eta` を書き替えるだけでは、お客様に届きません。**
`eta` を直したうえで、**必ず `reports` に経過報告を1件足してください。**
（足しかたは「3. 直ったときのお知らせ」と同じ。`reports` の `[` のすぐ後ろです）

```json
        {
          "kind": "progress",
          "at": "2026-09-05T14:50:00+09:00",
          "body": "復旧の見込みを、本日18時ごろに変更いたしました。ご迷惑をおかけしております。"
        },
```

理由は、アプリの帯（バナー）のしくみです。
お客様が帯の「閉じる」を押すと、その帯は**新しい報告が足されるまで出てきません**。
`eta` の文字だけを直しても、**すでに帯を閉じたお客様の画面は何も変わりません。**

「15時に直る予定が18時になりました」は、いちばんお伝えしたいことです。
報告を1件足せば帯がもう一度出て、新しい見込みが届きます。**必ず足してください。**

## 5. アプリの帯（バナー）を引っ込める

復旧報告を出してから数日たったら、そのお知らせの `"showInApp": true` を
`"showInApp": false` に書き替えてください。
アプリの帯は消えますが、**このページには記録として残ります**（消さないでください）。

## 6. 計画メンテナンスの予告

`"type"` を `"maintenance"`、`"kind"` を `"progress"` にして、**4日前まで**に出します。

```json
    {
      "id": "2026-09-20-maintenance",
      "type": "maintenance",
      "title": "9月20日（土）にシステムの保守作業を行います",
      "scope": "すべてのお客様（作業中は牛カードをご利用いただけません）",
      "eta": "9月20日 22:00〜23:00（時刻は前後する可能性があります）",
      "showInApp": true,
      "reports": [
        {
          "kind": "progress",
          "at": "2026-09-16T09:00:00+09:00",
          "body": "9月20日（土）22時から23時ごろまで、システムの保守作業のため牛カードをご利用いただけません。時刻は前後する可能性があります。ご不便をおかけしますが、よろしくお願いいたします。"
        }
      ]
    }
```

作業が終わったら `"kind": "recovery"` の報告を足します。

## 7. 保存する

1. 画面右上の緑のボタン（**Commit changes...**）を押す
2. 出てきた小窓で、もう一度 **Commit changes** を押す
3. **1〜2分待ってから** https://status.ushi-card.com/ を開き、**思ったとおりに出ているか必ず目で確かめる**
4. 続けて**牛カードのアプリも開き、画面のいちばん上に帯（バナー）が出ていることを目で確かめる**
   （`"showInApp": true` にしたお知らせだけが帯になります）

> ⚠️ **稼働状況ページとアプリの帯、2つとも見て、はじめて「お知らせが出せた」ことになります。**
> **ページには出ているのに、アプリの帯だけ出ない**ということが起こります。
> アプリは、書き方が少しでも違うお知らせを黙って読み飛ばすためです。
> よくある例:
> - `showInApp` を `showinapp` のように小文字で書いた
> - `kind` の綴りを間違えた（`recovry` など）
> - `id` を書き忘れた
>
> 稼働状況ページはこれらを大目に見て表示しますが、**アプリは表示しません。**
> ページだけを見て安心すると、いちばんお知らせが必要なお客様に何も届きません。
> 帯が出ないときは、`status.json` の書き方を「書ける項目の一覧」（下の表）と1文字ずつ見比べてください。

> ⚠️ **アプリの帯は、出るまでに最大5分かかります。**
> アプリは5分おきにお知らせを見に行くしくみのためです。
> すぐに確かめたいときは、アプリの画面を**再読み込み（リロード）**してください。すぐに出ます。
> 5分待っても、再読み込みしても出ないときは、書き方が違っています。

> ⚠️ カンマ（`,`）や波かっこ（`{` `}`）を1つ消しただけでも、ページ全体が
> 「稼働状況を読み込めませんでした」になります。**保存したら必ずページを開いて確かめてください。**
> おかしくなったら、GitHub の画面で `status.json` の **History**（履歴）から
> 1つ前の内容に戻せます。

# 書ける項目の一覧

| 項目 | 必須 | 書くこと |
|---|---|---|
| `id` | ○ | このお知らせの名札。`日付-短い英語` の形で、**他と重複しない**ものを付ける。一度付けたら変えない（変えると、閉じた帯がお客様の画面に出直します） |
| `type` | ○ | `incident`（障害）／ `maintenance`（メンテナンス）／ `info`（お知らせ・規約改定の周知など） |
| `title` | ○ | 一行の見出し |
| `scope` | | 影響範囲（例:「すべてのお客様」「組合の管理者のみ」） |
| `eta` | | 復旧見込み／実施予定時間帯。復旧後は実際の復旧日時に書き替えてよい。**見込みの時刻が変わったときは、ここを直すだけでは届きません**（「4. 復旧の見込み時刻が変わったとき」を読んでください） |
| `showInApp` | ○ | `true` ならアプリの画面上部にも帯を出す。`false` ならこのページにだけ残す |
| `reports` | ○ | 報告の並び。1件以上 |
| `reports[].kind` | ○ | `incident`（障害報告）／ `progress`（経過報告）／ `recovery`（復旧報告） |
| `reports[].at` | ○ | 日時。`2026-09-05T13:20:00+09:00` の形（末尾の `+09:00` は日本時間の意味。必ず付ける） |
| `reports[].body` | ○ | 本文 |

お知らせが1件も無いときは、こう書きます（これが平常時の姿です）。

```json
{
  "notices": []
}
```

# このリポジトリに入れてよいもの

**静的なHTML・CSS・JavaScript と、告知用の `status.json` だけです。**

このリポジトリは **公開（Public）** です。GitHub の無料プランでは、
非公開リポジトリから Pages を公開できないためです。

牛カード本体のソースコード・設定・パスワード・接続文字列・お客様の情報は
**1バイトも置かないでください。**
（`index.html` に書いてある本番アプリのURLは、もともと誰でもアクセスできる公開URLです）

## お知らせの本文に書いてはいけないこと

**パスワードやログイン情報を入力させる文言は、絶対に書かないでください。**
「本人確認のため、パスワードをもう一度ご入力ください」
「下記のリンクからログインし直してください」といった案内も同じです。

ここに書いた文章は、**ログイン画面をふくむ牛カードの全画面に、赤い帯として出ます。**
お客様には「牛カードが出した公式の案内」に見えるので、そのまま入力してしまいます。
万一このリポジトリが乗っ取られたときに被害を大きくしないためにも、
**この形の文章は、正しい用事であっても書かない**ことにしています。
パスワードの再設定をお願いしたいときは、電話またはメールでご案内してください。

# 運営者向けメモ

- 告知は4層で行います（①アプリ内の帯 ②電話 ③メール ④このページ）。
  **顧客が1〜10件の段階では電話が主手段**で、このページと帯はその補助です。
  詳しい手順は牛カード本体のリポジトリ `docs/DEPLOYMENT.md`「障害・メンテナンス時の告知手順」にあります。
- 原因が牛カードの外にあることもあります。まず上流の稼働状況を確認してください。
  - Supabase: https://status.supabase.com/
  - Google Cloud: https://status.cloud.google.com/
  - Resend（メール送信）: https://resend-status.com/
- このページは検索エンジンに載せない設定（`noindex`）にしています。
- 古いお知らせは消さない運用のため、**年数がたつと1ページに全履歴が並びます。**
  読みづらくなったら、そのときに古い分のまとめかたを考えます（いまは対応不要）。
- `main` ブランチには、強制上書き（force push）とブランチ削除の禁止をかけています。
  ふだんの保存（Commit changes）はこれまでどおりできます。
